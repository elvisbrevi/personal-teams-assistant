The Wiki needs a compatible CLI and host (0.3.0 or later). Use `pta --version`, `capabilities` and `status`; close an old host with `pta app quit` before using new executables. Do not install, reinstall, publish or change the GUI as a requirement of this operation. The CLI rejects the Wiki schema when the host's descriptor does not announce support.

First audit `pta --json credentials list` and the existing Azure reference in the configuration. Inspecting metadata does not decrypt the secret on macOS. If another variable has to be resolved, apply the credentials skill (`lz credentials-audit --name AZURE_DEVOPS_TOKEN`) and reuse its location; never print a PAT or pass it as an argument or in a URL. Wiki/Search need `vso.wiki`; Git Items/Commits for authorship need `vso.code`. A 403 never authorizes widening audiences or changing the Teams OAuth.

Add with `sources add` a `kind=tool` resource, initially disabled, without audiences or external processing. Its tool is `{"type":"azure_devops_wiki","repository":"ALIAS","path":"CATALOG.toml","secret_ref":"EXISTING_REFERENCE","wiki_ids":[],"author_mode":"prefer_mine"}`. Do not copy the activity source's global permissions. The existing catalog keeps organizations, projects and `author_email`; `wiki_ids` narrows the scope. Modes: `prefer_mine`, `mine_only` (verified own creation OR edit) and `all`. A query override changes the selection, never permissions or attribution.

`pta --json azure wiki list SOURCE_ID` discovers metadata even while disabled. To query, enable the source; `search/read` are local and need neither external_processing nor a Teams audience. Search reads JSON on stdin: `{"query":"continuous deployment","wiki_id":null,"author_mode":"all"}`. Read reads `{"wiki_id":"UUID","path":"/Canonical path"}`. Use exactly the Wiki path returned; never convert `.md`, spaces, hyphens or `%` by hand. Never accept an arbitrary organization or URL.

Check `ok`, `data.partial`, `warnings`, the pages and `reference`: wiki, project, version, URL, authority and attribution. `revision` is the ETag; `git_revision`/reference.revision keep the commit verified through Git Items against that content. Unknown authorship or a Git failure does not prove a lack of participation. Never call the last editor the creator; never show email addresses. An unauthorized source or an unread document never supports an answer.

Limits: 30 seconds per Wiki search, requests of at most 8 seconds, 1 MB, Search 25/100 candidates, up to 10 history checks and four context pages. Partial coverage is reported for indexing, pagination, network, paths without a link and incomplete reads or authorship. There is no content cache and pages are never modified.

For `pta chat` or `test simulate`, authorize external_processing on that source with `sources audience`, keeping the independent local audiences. `sources` in the simulation request selects the resource explicitly and grants no Teams permission. Ask with the topic in the first sentence. A follow-up within 30 minutes in the same conversation may omit it («¿y si quiero pagar 2 servicios?»): it is rewritten with the previous exchange and the Wiki is searched for the resolved topic; that resolved question becomes the context of the next turn. An explicit Wiki request and usage/configuration questions take priority over activity words such as pipeline; «cómo funciona la notificación de pagos» / "how does the payment notification work" also reads documentation. No model selects or vetoes tools before searching: ambiguous messages are classified as a question, an activity review, a request for the person, a greeting or information, and questions may retrieve authorized knowledge. A single Wiki source serves documentary reads; other ambiguous scopes are chosen among authorized capabilities by the model chain. A normal answer reads one tool; only an activity review combines tools. The result must link every page used and attribute third-party or unknown authorship, in a final «Fuentes» section («Sources» with `llm.language = "en"`) whose link text is the page title; Teams receives the answer as HTML and `pta chat` returns it as Markdown. Code checks the citations, work items/pipelines/stages and relevant interlocutors' names against the complete answer before sending it. Never trim citations after those checks. Simulating never sends to Graph.

In an activity review, the Wiki source contributes the pages the user created or edited in the window, from each wiki's Git history (own commits only), each with its verified link; a page whose change names a work item (`#123`, `AB#123`, «HU 8765») counts as registered.

Done when: real list/search/read, content, revision and link checked, and a simulation backed by an accessible page; audiences kept. To verify a real edit, the person must edit an authorized page and say so, to repeat the read; never write to the Wiki as part of a read-only test. Report separately the controlled update regression and any real edit not observed.
