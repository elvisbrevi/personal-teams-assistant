Read `pta config show` or `pta config get policy.dry_run`. `pta config set policy.dry_run true` keeps the other fields and validates before applying. The last argument is JSON, including quotes for strings. Every existing field can be edited by its dotted path; objects, lists and optional fields are replaced as whole JSON values.

`knowledge_index` holds the optional embeddings endpoint for semantic search of repositories and notes (`embeddings`: `url`, `model`, `secret_ref`); see [auth-and-knowledge.md](auth-and-knowledge.md). Without it, they are searched by their words.

`activity_registration` configures daily snapshots of existing Azure tasks, their schedule, Azure sources and advisory hours target. It defaults to disabled; snapshots never write to Azure and need no model. Legacy task-write fields are ignored. See [activity-registration.md](activity-registration.md).

`pta config apply` and `pta config validate` read JSON or TOML on stdin with `config`, `map` and, optionally, `tunnel_config`. Start from a recent read. Writes based on a read detect revision changes; after a conflict, read again and redo the change. The GUI takes part in the same control: it collects Settings and Knowledge changes in the «You have unsaved changes» bar and writes nothing until «Save changes» (credentials are stored right away). Validation and import keep the map and identity restrictions.

A profile written before 0.6.1 may still have a `[jev]` section (an external classifier the app no longer uses). It loads and is dropped the next time the profile is saved; `pta config set jev.*` is rejected as an unknown field. A host or CLI older than 0.6.1 cannot load a profile saved by 0.6.1 or later.

`pta mode observe` and `pta mode active` persist the mode and apply it to the running service; verify with `pta mode show`. Observation jobs stay deduplicated.

Application credentials are account-owned stored variables (a name, description and encrypted value): see [account variables](variables.md). `pta credentials list` returns names and origins; `unused` marks a credential that is allowed but not required by the current configuration (e.g. `DEEPSEEK_API_KEY` without DeepSeek in the model chain), and `retired` one that an earlier version needed and nothing reads now (`TYPESAFE_API_KEY` and `AZURE_IMPLEMENTATION_WRITE_TOKEN`): it can be removed with `pta credentials delete NAME` but not set. `pta credentials set NAME` reads the value from stdin, at most 16 KiB; application values update immediately; restart a running assistant to use the new value. Internal keys still require a stopped service. The allowlist comes from the configuration. The key of an existing encrypted database is kept. The agent may accept access to existing credentials the authorized operation needs, under the permission rule of [the skill](../SKILL.md). Reuse the audited locations first; never print secrets. If the tool blocks the dialog or macOS demands in-person authentication, report that concrete blocker and ask only for the intervention needed, without asking for another credential.

`pta config import FILE` needs the service stopped, resolves relative paths against the imported file and keeps the existing data directory and key. A database is never reused with another Microsoft identity.

Language models: `llm.chain` is the ordered list `{provider, model, effort, enabled}` with `provider` in `codex`, `claude`, `opencode` (OpenCode 2; installed CLI with its own login; the app needs no credential) or `deepseek` (API with `DEEPSEEK_API_KEY`). The chain holds up to 16 entries; the same provider or model can appear several times with independent models and efforts. In Settings → Language models, use Add model, choose a provider and configure each row, or remove it. The chain classifies ambiguous messages, writes answers and picks the references an answer uses. Every model call starts with the first active provider and moves to the next only if it fails (no credits, usage limit, missing CLI, an answer outside the JSON contract or another error); the next call starts with the first again. `pta --json llm providers` lists the detected CLIs, their version, models and supported efforts (Codex from `codex debug models`; OpenCode 2 from `opencode api --standalone model.list`, filtered by TUI favorites; Claude and DeepSeek from a fixed list). Efforts: Codex `minimal|low|medium|high|xhigh|max` (never `ultra`, which delegates to sub-agents), Claude `low|medium|high|xhigh|max`, DeepSeek `none|low|high|max` (`none` turns reasoning off). OpenCode 2 uses `provider/model` IDs. Its GUI uses a dropdown with only available models marked as favorites in OpenCode on the host; mark favorites there, then use Detect CLIs again. It reads `favorite` from `model.json` in the state directory reported by `opencode debug paths state`. No favorites or unreadable preferences/metadata means no choices and Add model is disabled for OpenCode. Effort offers `default` (the model default) and the exact variant IDs reported for that model, including `none`, `minimal` or other names when supported. Switching models resets an unsupported effort to `default`. Existing non-favorite models and unsupported efforts stay saved with a notice, without appearing as choices. CLI configuration accepts safe variant IDs; OpenCode checks support when invoked. Discovery and execution use the same isolated configuration, without user/project customizations. It runs with tools and external integrations denied, in a private server with a fresh session deleted after each call. Log in with OpenCode itself first; no provider key is copied into the app. Example: `pta config set llm.chain '[{"provider":"codex","model":"gpt-6.1-sol","effort":"medium"},{"provider":"claude","model":"claude-opus-5-5","effort":"medium"},{"provider":"deepseek","model":"deepseek-flash","effort":"max"}]'`. With an empty `chain` the legacy profile applies (`llm.provider`/`llm.model`, DeepSeek at maximum effort). `DEEPSEEK_API_KEY` is required at start only while DeepSeek is active. Check each provider with `pta test providers`.

Language: `llm.language` (`"es"` by default, or `"en"`) sets the language of everything the assistant sends to Teams: the answer, the holding notice, the withheld-answer notice, the thanks for a shared link («Gracias Victoria.» / «Thanks Victoria.») and the closing sentence that links Wiki pages («Más detalle en …» / «More detail in …»). It overrides any language `llm.style` names. It also sets the language of the GUI (native and web, reloaded once after the change) and of the activity tasks the agents draft (titles, descriptions, questions) and the explanations stored with them. It does not change the audit log, diagnostics or CLI (all in English) or the `policy.greeting` text. Example: `pta config set llm.language '"en"'`; in the GUI, Settings → General → «Language».

Voice: every answer is written as the user replying to a colleague — natural, warm and professional, neither robotic nor vulgar or overly casual — without the app's internal terms (evidence, sources, verification), stock disclaimers or menus of options. That base is fixed in the generation prompt; `llm.style` adds preferences on top of it (length, structure, emphasis).

Message style in Teams: `message_style` sends what the assistant writes in Teams (answers and the holding and withheld notices) as an Adaptive Card with a colored stripe along the left edge and a band with a label, instead of plain HTML. It is off by default. Fields: `enabled`; `label` (one line, up to 80 characters; empty uses «Respuesta generada con IA» or "AI-generated response" by `llm.language`); `position` (`"bottom"` or `"top"`); `accent` (the stripe, any `"#RRGGBB"`); `band` (`"accent"` lavender, `"emphasis"` gray, `"good"`, `"warning"`, `"attention"` or `"none"`) and `label_color` (`"default"`, `"subtle"`, `"accent"`, `"good"`, `"warning"`, `"attention"`), which Teams shades for its light or dark theme; `icon` (an emoji before the label) and `emoji` (any one emoji, default 🤖); `band_height` (the band's least height in pixels, 24 to 160; 0, the default, fits the text); `stripe_width` (pixels, 2 to 16, default 4); `text_size` (the message's text, default `"default"`; headings stay a step larger) and `label_size` (the band's text and emoji, default `"small"`), each `"small"`, `"default"`, `"medium"`, `"large"` or `"extralarge"`, which Teams turns into its own sizes. Example: `pta config set message_style.enabled true`, `pta config set message_style.label '"Escrito con IA"'`, `pta config set message_style.position '"top"'`, `pta config set message_style.stripe_width 8`, `pta config set message_style.emoji '"✨"'`, `pta config set message_style.band_height 48`, `pta config set message_style.text_size '"large"'`; MCP `message_style` and `message_style_update`; in the GUI, Settings → General → «Message style in Teams», with color combinations and a preview. Messages posted with `pta teams send`/`teams_post` use the same style, except one with `@[Name]` mentions or with images, which stays plain HTML because Teams mentions and embedded images live in the HTML body (the card never carries an image); a message whose card would not fit in one Teams message is sent as plain HTML. The style belongs to the account: it synchronizes to every computer of the account (0.12.13+), so a message posted from any of them looks the same, and it can be changed from any of them.

Teams chats: `graph.discover_all_chats`, `graph.allowed_chats` and the personal chat are what this computer receives and answers, and stay its own. `teams_reading` (`all_chats`, `personal_chat`, `chats`; off and omitted while unchanged) is the account's: the chats every computer of the account may read on request with `pta teams`. See [account configuration](account-configuration.md#teams-chats-read-on-request).

Answers have no character or token limit: `policy.max_answer_chars` and `policy.max_detailed_answer_chars` are kept for compatibility but not applied. Only an answer whose HTML does not fit in a Teams message is withheld. DeepSeek calls have no deadline; a CLI call is cut after 20 minutes and the next provider answers. `pta chat` and `pta test providers` wait as long as it takes. In Teams, if no answer is ready after 5 minutes, «Déjame revisarlo.» («Let me look into it.» with `llm.language = "en"`) is sent once and the final answer follows (`audit.holding_reply`). `policy.max_message_age_seconds` is measured when processing starts, not when sending.

Application credentials (0.10.1+) are stored variables: use Settings › Variables or `pta variables`. Existing configured values migrate automatically and are verified before use; the old stores remain recovery copies. The `credentials set/delete` compatibility commands change the same entries. Internal encryption/session/hosting keys keep their existing local stores and protections. See [variables.md](variables.md#application-credentials-are-variables-0101).
