Read `pta config show` or `pta config get policy.dry_run`. `pta config set policy.dry_run true` keeps the other fields and validates before applying. The last argument is JSON, including quotes for strings. Every existing field can be edited by its dotted path; objects, lists and optional fields are replaced as whole JSON values.

`activity_registration` configures scheduled/manual registration of performed work as completed tasks, the 9-hour target, source selection and required fields. Every setting and review action is available through `pta`: see [activity-registration.md](activity-registration.md). It defaults to disabled; observation mode also prevents task creation.

`pta config apply` and `pta config validate` read JSON or TOML on stdin with `config`, `map` and, optionally, `tunnel_config`. Start from a recent read. Writes based on a read detect revision changes; after a conflict, read again and redo the change. The GUI takes part in the same control: it collects Settings and Knowledge changes in the «You have unsaved changes» bar and writes nothing until «Save changes» (credentials are stored right away). Validation and import keep the map and identity restrictions.

A profile written before 0.6.1 may still have a `[jev]` section (an external classifier the app no longer uses). It loads and is dropped the next time the profile is saved; `pta config set jev.*` is rejected as an unknown field. A host or CLI older than 0.6.1 cannot load a profile saved by 0.6.1 or later.

`pta mode observe` and `pta mode active` persist the mode and apply it to the running service; verify with `pta mode show`. Observation jobs stay deduplicated.

`pta credentials list` returns names and origins; `unused` marks a credential that is allowed but not required by the current configuration (e.g. `DEEPSEEK_API_KEY` without DeepSeek in the model chain), and `retired` one that an earlier version needed and nothing reads now (`TYPESAFE_API_KEY`): it can be removed with `pta credentials delete NAME` but not set. `pta credentials set NAME` reads the value from stdin, at most 16 KiB; the service must be stopped. The allowlist comes from the configuration. The key of an existing encrypted database is kept. The agent may accept access to existing credentials the authorized operation needs, under the permission rule of [the skill](../SKILL.md). Reuse the audited locations first; never print secrets. If the tool blocks the dialog or macOS demands in-person authentication, report that concrete blocker and ask only for the intervention needed, without asking for another credential.

`pta config import FILE` needs the service stopped, resolves relative paths against the imported file and keeps the existing data directory and key. A database is never reused with another Microsoft identity.

Language models: `llm.chain` is the ordered list `{provider, model, effort, enabled}` with `provider` in `codex`, `claude` (installed CLI with its own login; the app needs no credential) or `deepseek` (API with `DEEPSEEK_API_KEY`). Each provider appears once. The chain classifies ambiguous messages, writes answers and picks the references an answer uses. Every model call starts with the first active provider and moves to the next only if it fails (no credits, usage limit, missing CLI, an answer outside the JSON contract or another error); the next call starts with the first again. `pta --json llm providers` lists the detected CLIs, their version, models and supported efforts (Codex from `codex debug models`; Claude and DeepSeek from a fixed list). Efforts: Codex `minimal|low|medium|high|xhigh|max` (never `ultra`, which delegates to sub-agents), Claude `low|medium|high|xhigh|max`, DeepSeek `none|low|high|max` (`none` turns reasoning off). Example: `pta config set llm.chain '[{"provider":"codex","model":"gpt-6.1-sol","effort":"medium"},{"provider":"claude","model":"claude-opus-5-5","effort":"medium"},{"provider":"deepseek","model":"deepseek-flash","effort":"max"}]'`. With an empty `chain` the legacy profile applies (`llm.provider`/`llm.model`, DeepSeek at maximum effort). `DEEPSEEK_API_KEY` is required at start only while DeepSeek is active. Check each provider with `pta test providers`.

Language: `llm.language` (`"es"` by default, or `"en"`) sets the language of everything the assistant sends to Teams: the answer, the holding notice, the withheld-answer notice and the final sources section. It overrides any language `llm.style` names. It does not change the app's interface, audit log or CLI (all in English) or the `policy.greeting` text. Example: `pta config set llm.language '"en"'`; in the GUI, Settings → Answers → «Answer language».

Answers have no character or token limit: `policy.max_answer_chars` and `policy.max_detailed_answer_chars` are kept for compatibility but not applied. Only an answer whose HTML does not fit in a Teams message is withheld. DeepSeek calls have no deadline; a CLI call is cut after 20 minutes and the next provider answers. `pta chat` and `pta test providers` wait as long as it takes. In Teams, if no answer is ready after 5 minutes, «Déjame revisarlo.» («Let me look into it.» with `llm.language = "en"`) is sent once and the final answer follows (`audit.holding_reply`). `policy.max_message_age_seconds` is measured when processing starts, not when sending.
