Consulta `pta config show` o `pta config get policy.dry_run`. `pta config set policy.dry_run true` conserva los demás campos y valida antes de aplicar. El último argumento es JSON, incluyendo comillas para strings. Todos los campos existentes se pueden editar por su ruta con puntos; objetos, listas y campos opcionales se reemplazan como JSON completo.

`pta config apply` y `pta config validate` leen JSON o TOML de stdin con `config`, `map` y, opcionalmente, `tunnel_config`. Parte de una consulta reciente. Las escrituras basadas en una consulta detectan cambios de revisión; tras conflicto, vuelve a leer y rehace el cambio. La GUI también participa del mismo control: acumula los cambios de Configuración y Conocimiento en la barra «Cambios sin guardar» y no escribe nada hasta «Guardar cambios» (las credenciales se guardan al momento). Validación e importación conservan las restricciones del mapa y de identidad.

`pta mode observe` y `pta mode active` persisten y aplican el modo al servicio existente; verifica `pta mode show`. Los jobs de observación permanecen deduplicados.

`pta credentials list` devuelve nombres y procedencia; `unused` indica una credencial permitida pero no requerida por la configuración actual (p. ej. `DEEPSEEK_API_KEY` sin DeepSeek en la cadena de modelos). `pta credentials set NAME` lee el valor por stdin, limitado a 16 KiB; debe estar detenido el servicio. La allowlist viene de la configuración. La clave de una base cifrada existente se conserva. El agente puede aceptar el acceso a credenciales existentes necesario para la operación autorizada, según la regla de permisos de [la skill](../SKILL.md). Primero reutiliza las ubicaciones auditadas; nunca imprime secretos. Si el control del diálogo está bloqueado por la herramienta o macOS exige autenticación presencial, informa ese impedimento concreto y pide únicamente la intervención necesaria, sin solicitar otra credencial.

`pta config import FILE` requiere servicio detenido, resuelve rutas relativas contra el archivo importado y mantiene el directorio de datos y la clave existentes. Una base no se reutiliza con otra identidad Microsoft.

Modelos de lenguaje: `llm.chain` es la lista ordenada `{provider, model, effort, enabled}` con `provider` en `codex`, `claude` (CLI instalada, usa su propia sesión; no hace falta credencial en la app) o `deepseek` (API con `DEEPSEEK_API_KEY`). Cada proveedor aparece una vez. Cada llamada al modelo empieza por el primero activo y pasa al siguiente solo si falla (sin créditos, límite de uso, CLI ausente u otro error); la siguiente llamada vuelve a empezar por el primero. `pta --json llm providers` lista las CLI detectadas, su versión, modelos y esfuerzos admitidos (Codex desde `codex debug models`; Claude y DeepSeek con lista fija). Esfuerzos: Codex `minimal|low|medium|high|xhigh|max` (nunca `ultra`, que delega en subagentes), Claude `low|medium|high|xhigh|max`, DeepSeek `none|low|high|max` (`none` desactiva el razonamiento). Ejemplo: `pta config set llm.chain '[{"provider":"codex","model":"gpt-6.1-sol","effort":"medium"},{"provider":"claude","model":"claude-opus-5-5","effort":"medium"},{"provider":"deepseek","model":"deepseek-flash","effort":"max"}]'`. Con `chain` vacío rige el perfil heredado (`llm.provider`/`llm.model`, DeepSeek con esfuerzo máximo). `DEEPSEEK_API_KEY` solo se exige al iniciar si DeepSeek está activo. Verifica cada proveedor con `pta test providers`.

Idioma: `llm.language` (`"es"` por defecto, o `"en"`) fija el idioma de todo lo que el asistente envía a Teams: la respuesta, el aviso de espera, el aviso de respuesta retenida y la sección final de fuentes. Prevalece sobre cualquier idioma que nombre `llm.style`. No cambia la interfaz de la app, la auditoría, el CLI ni el saludo de `policy.greeting`. Ejemplo: `pta config set llm.language '"en"'`; en la GUI, Configuración → Respuestas → «Idioma de las respuestas».

Las respuestas no tienen límite de caracteres ni de tokens: `policy.max_answer_chars` y `policy.max_detailed_answer_chars` se conservan por compatibilidad pero no se aplican. Solo se descarta una respuesta cuyo HTML no cabe en un mensaje de Teams. Las llamadas a DeepSeek no tienen plazo; las de una CLI se cortan a los 20 minutos y pasan al siguiente proveedor. `pta chat` y `pta test providers` esperan lo que tarde. En Teams, si a los 5 minutos aún no hay respuesta, se envía una vez «Déjame revisarlo.» («Let me look into it.» con `llm.language = "en"`) y después la respuesta final (`audit.holding_reply`). `policy.max_message_age_seconds` se mide al empezar a procesar, no al enviar.
