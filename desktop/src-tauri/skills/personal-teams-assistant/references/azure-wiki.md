Wiki requiere CLI y host compatibles (núcleo/host 0.3.0 del checkout; la distribución 0.2.0 no lo implementa). Usa `pta --version`, `capabilities` y `status`; ante host antiguo cierra ese host antes de usar los dos ejecutables de la compilación nueva. No instalar/reinstalar/publicar ni modificar GUI como requisito de esta operación. El CLI rechaza el esquema Wiki cuando el descriptor no anuncia soporte.

Audita primero `pta --json credentials list` y la referencia de Azure existente en config. La inspección de metadatos no descifra el secreto en macOS. Si se necesita resolver una variable adicional, aplica la skill credentials (`lz credentials-audit --name AZURE_DEVOPS_TOKEN`) y reutiliza su ubicación; nunca imprimir un PAT ni pasarlo como argumento/URL. Wiki/Search necesitan `vso.wiki`; Git Items/Commits para autoría necesitan `vso.code`. Un 403 no autoriza ampliar audiencias ni cambiar OAuth de Teams.

Añade con `sources add` un recurso `kind=tool`, inicialmente deshabilitado, sin audiencias ni procesamiento externo. Su tool es `{"type":"azure_devops_wiki","repository":"ALIAS","path":"CATALOGO.toml","secret_ref":"REFERENCIA_EXISTENTE","wiki_ids":[],"author_mode":"prefer_mine"}`. No copiar permisos globales de actividad. El catálogo existente mantiene organizaciones, proyectos y `author_email`; `wiki_ids` restringe el alcance. Modos: `prefer_mine`, `mine_only` (creación O edición propia verificada) y `all`. Override de consulta cambia selección, no permisos ni atribución.

`pta --json azure wiki list SOURCE_ID` descubre metadatos incluso deshabilitada. Para consultar habilita la fuente; `search/read` son locales y no requieren external_processing ni audiencia Teams. Search recibe JSON por stdin: `{"query":"despliegue continuo","wiki_id":null,"author_mode":"all"}`. Read recibe `{"wiki_id":"UUID","path":"/Ruta canónica"}`. Usa exactamente la ruta Wiki retornada; no convertir `.md`, espacios, guiones ni `%` a mano. Nunca aceptar organización/URL arbitrarias.

Comprueba `ok`, `data.partial`, `warnings`, las páginas y `reference`: Wiki, proyecto, versión, URL, autoridad y atribución. `revision` es ETag; `git_revision`/reference.revision conservan commit verificado mediante Git Items contra ese contenido. Autoría desconocida o fallo Git no prueban ausencia de participación. No llamar creador al último editor; no mostrar correos. Una fuente no autorizada o un documento no leído nunca respalda una respuesta.

Límites: 30 segundos Wiki, peticiones de hasta 8 segundos, 1 MB, Search 25/100 candidatos, hasta 10 verificaciones y cuatro páginas de contexto. Se expone cobertura parcial por indexación, paginación, red, rutas sin enlace y lectura/autoría incompletas. No hay caché de contenido ni modificación de páginas.

Para `pta chat` o `test simulate`, autoriza external_processing en esa fuente mediante `sources audience`, conservando las audiencias locales independientes. `sources` en la petición de simulación selecciona explícitamente el recurso y no concede permisos Teams. Pregunta con el tema en la primera frase; Wiki explícita tiene prioridad sobre palabras de actividad como pipeline. El resultado debe incluir enlaces de todas las páginas usadas y atribución de terceros/desconocidos. Las citas, work items/pipelines/stages y nombres relevantes de interlocutores se validan con la respuesta completa antes de aprobarla. No recortar citas tras el control final. Simular nunca envía a Graph.

Cierre: list/search/read reales, contenido/revisión/enlace comprobados y simulación respaldada por página accesible; audiencias conservadas. Para verificar una edición real, la persona debe editar una página autorizada y avisar para repetir read; no escribir en Wiki como parte de una prueba de solo lectura. Reportar por separado la regresión de actualización controlada y cualquier edición real que no se haya observado.
