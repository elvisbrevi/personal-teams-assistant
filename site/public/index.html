Answers in Teams as you, and only with what you authorize.

It replies for you when someone messages you directly, mentions you, or when you ask it in your chat with yourself. It gathers evidence from your sources, drafts with Codex, Claude Code, OpenCode 2 or DeepSeek, checks references and known sensitive data in code, and never automatically retries a send.

From message to reply, with a check at every step

Models propose; code decides what can be read, what can be cited and what gets sent.

  1. 1

    Receives

    Microsoft Graph notifies it of every new message through a webhook. Your chat with yourself is also checked every 10 s.

  2. 2

    Decides whether to answer

    Only direct messages, real mentions or your chat with yourself. Calls, meetings and “got a minute?” are left to you.

  3. 3

    Gathers evidence

    It reads only the sources open to that conversation: Git repositories, URLs, Azure DevOps wikis and activity, verified notes and your own Teams messages.

  4. 4

    Drafts

    Your configured order of Codex, Claude Code, OpenCode 2 and DeepSeek. If one fails or runs out of credits, the next active provider answers; the following call starts again from your default.

  5. 5

    Verifies in code

    References, IDs, URLs and sensitive data. If something can't be checked, the reply is held back and you get a note in your chat with yourself.

  6. 6

    Sends once

    As Teams HTML, logged before it goes out. It never retries: when in doubt, the message is left for human review.

Built for people who answer the same questions again and again

Your own identity

It replies as you, not as a bot. A public Entra client with PKCE and only User.Read, Chat.Read, ChatMessage.Send and offline_access.

Sources with audiences

Every source starts disabled, with no audiences and no external processing. You decide which conversation can use what. Answers link the Wiki pages, work items and pipelines they cite.

Work you didn't log

Review your activity against existing work items, using the sources you authorize and verified links. Daily activity runs never create, link or change provider work items.

Daily activity records

Save existing Azure tasks by day, with verified links and registered hours. Schedule read-only snapshots and review saved days in Activities or with pta activity.

Observation mode

Start with drafts that are never sent. Review them in the app, rate them, keep the good ones as examples, and turn on sending once you trust them.

Every message, explained

What it decided, how it read the question, which model answered, what failed first and a log of every step, in the Messages tab or with pta audit.

On your desk and in your pocket

The tray app and your own private portal behind Cloudflare Access share one interface: add it to your phone's home screen and use it in light or dark.

App, CLI and agents

The pta CLI with stable JSON output, a built-in skill, and pta mcp: an MCP server so Claude Code, Codex or any client can operate it. Sending, access changes and implementation actions are marked for confirmation.

A private installation you control

Run it on your own computer or server, with your own accounts, credentials and HTTPS address. Each portal accepts only the GitHub owner you configure. The maintainer's portal is private.

Security policy Set up your portal

You configure Cloudflare Access, TLS and edge HSTS, SSH keys and a firewall for your host. Profiles share your OS account; selected coding directories are not OS isolation for untrusted code. The security policy tracks these limits and upstream dependency notices.

  • Owner-only sign-in. Your Cloudflare Access configuration and a locally bound GitHub identity protect your portal. There is no public registration.
  • Machines you approve. Authorize each new machine locally on your coordinator. Its private pairing file expires in ten minutes and works once, for that machine and installation.
  • Protected web sessions. Signed identity assertions, expiring and revocable sessions, protected cookies and Origin/CSRF checks guard browser operations. HTTPS origin responses include HSTS.
  • Credentials under your control. Use macOS Keychain, Windows Credential Manager or private profile files on Linux. Stored Microsoft OAuth tokens are encrypted.
  • Model decisions grant no access. Code checks audiences, paths and URLs. Answer generation runs without tools, with configured redaction for known secrets and sensitive patterns. Coding agents use their selected implementation permissions.
  • Activity records are read-only. Creating work items uses separate workflows that need your confirmation. An uncertain Teams send is left for review and never automatically retried.
  • Checks before delivery. Source and history secret scans, RustSec and GitHub dependency advisories, required CI checks and weekly audits support the public repository.

A single Cargo package

It installs the app, the host and the pta CLI on your own machine. You supply the accounts, credentials and hosting; your profile carries over between versions.

macOS and Windows

Tray app, host and CLI. cargo binstall downloads the prebuilt release in seconds; cargo install compiles it and needs the Tauri 2 prerequisites. Both need Rust and Git.

# prebuilt, in seconds
cargo binstall personal-teams-assistant
# or compiled here
cargo install personal-teams-assistant --locked
personal-teams-assistant  # opens the app

Linux and servers

No Tauri or WebKit: it is operated with pta, runs as a systemd service and can serve the web portal.

cargo install personal-teams-assistant \
  --no-default-features --locked
personal-teams-assistant --headless --start
  1. 1

    Configure

    Save your own provider credentials, pick the reply language and model order, and register your own Entra app. Its Home tab tells you what's missing.

    pta status
  2. 2

    Connect

    Sign in with your Microsoft account and expose the local port through your own stable HTTPS URL, for example with your own Cloudflare Tunnel.

    pta auth microsoft login
  3. 3

    Observe

    Authorize your sources, start the assistant and review its drafts without sending anything.

    pta start
  4. 4

    Go live

    Once you trust the drafts, turn off observation mode.

    pta mode active

To receive messages, the machine running the assistant must be on and reachable through a public HTTPS URL. Use your own Cloudflare Access configuration for the private web portal. Don't run two active instances for the same account.
